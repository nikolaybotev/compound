# This repo

A zero-dependency Node.js calculator for a fixed monthly mortgage payment and its amortization, and for the prepaid finance charge implied by a note rate and an APR. The skill at `.agents/skills/mortgage-loan-calculator/SKILL.md` asks for missing facts before it answers, for a fixed-rate loan and for a fixed-then-adjusting ARM. The design is `intent/mortgage-skill/`. The fee skill is `.agents/skills/mortgage-origination-fees/SKILL.md`. Its design is `intent/origination-fees/`. The ARM concepts skill is `.agents/skills/arm-loan-concepts/SKILL.md`. Its design is `intent/arm-concepts/`. That skill runs nothing and does not compute a payment, rate, or index for a person's loan. Its Types section may quote labeled illustrations of the page's general scenario and one CFPB sample.

## Commands

- Install: `mise install` in the repo root installs the Node.js version from `mise.toml`. Otherwise use that version.
- Run: `node compound_interest_monthly.js --amount 855000 --rate 6.99 --years 30` (healthy: a summary whose monthly payment is 5,682.60). `--amount` and `--rate` are required. Exactly one of `--years` or `--months` is required.
- JSON: add `--json`. Month rows: add `--schedule` (CSV alone, or inside the JSON object when combined with `--json`).
- Extra principal: `--extra fixtures/first-year-100.csv`. The header is `month,extra`. On $570,000 at 7% for 30 years, $100 in months 1–12 saves 813770 cents and pays off in month 358.
- Level extras, recast, funding, prevailing, and picture: `--level` (ARM mode) rewrites extras from the form `--extra` map; `--recast-month` prints a fixed-rate recast; `--funding YYYY-MM` adds payoff date and schedule accrual columns without changing the walk; `--prevailing` and picture flags (`--price`, `--tax`, `--insurance`, `--pmi`, `--fico`, `--closing`, and companions) print housing and closing lines from `picture.js`. The schedule CSV adds `saved_by_extra` after `interest_saved`. Design: `intent/library-cli-parity/`.
- Skill: `.agents/skills/mortgage-loan-calculator/SKILL.md`. It runs `scripts/compound_interest_monthly.js`, a symlink to the calculator at the repo root. The workspace link is local setup and is not committed.
- ARM: `node compound_interest_monthly.js --amount 570000 --rate 5.875 --years 30 --fixed-years 7 --adjust-months 12 --margin 2.5 --caps 5/2/5 --floor 2.5` (healthy: monthly payment 3,371.77, `Highest rate: 10.875% (from month 85)`, `Highest payment: 5,037.71 (from month 85)`, `Adjustments: 23`, then `Ceiling: 10.875% / Floor: 2.5%`, `First adjustment month 85: -941.16 to +1,665.94`, `Even-out extra: 823.21`, `Monthly extra: 823.21`). `--even-yearly`, `--even-month`, and `--start` join the ARM flags; every ARM run passes `arm.adjustmentStats` (`{}` with no positive yearly extra). ARM mode is on when any ARM flag is present: `--fixed-years` or `--fixed-months` (exactly one), `--adjust-months`, `--margin`, `--caps` (initial/periodic/lifetime), `--floor` are required together; `--initial-floor`, `--round-eighth`, and `--index FILE` (header `month,index`, rows only at adjustment months) are optional. `--index fixtures/index-4.42-first-reset.csv` reproduces the 4.42% first-reset run (interest 106408179 cents). Design: `intent/arm-loan/`.
- Origination fees: `node origination_fees.js --amount 600000 --rate 6.75 --apr 7.21 --years 30` (healthy: prepaid finance charge 27,257.20, points 4.543%). `--amount` or `--price` with `--down` or `--down-percent`, plus `--rate`, `--apr`, and exactly one of `--years` or `--months`, are required. `--json` reports integer cents. Skill: `.agents/skills/mortgage-origination-fees/SKILL.md`. It runs `scripts/origination_fees.js`, a symlink to that script. When the user omits the term it passes `--years 30` and says so. The workspace link is local setup and is not committed.
- Test: `node --test` or `mise run test` (same `node --test` task in `mise.toml`). The suite collects `amortize.test.js`, `calendar.test.js`, `picture.test.js`, and `arm_loan_concepts.test.js` for the ARM concepts skill.
- Page: `pnpm --dir apps/web dev` serves the amortization page. `pnpm --dir apps/web build` writes `apps/web/dist` with Vite `base` `./` unless `VITE_BASE` is set. `pnpm --dir apps/web preview` serves that build. `pnpm --dir apps/web test` runs the page unit tests. `pnpm --dir apps/web test:e2e` runs Playwright against `vite preview` (first time: `pnpm --dir apps/web exec playwright install --with-deps chromium`).
- Lint: none.
- CI: `.github/workflows/test.yml` runs `node --test` on the Node.js version in `mise.toml` with no install step, and a second job on that version that installs the web app with pnpm and runs its unit tests and Playwright. `.github/workflows/codeql.yml` (workflow `CodeQL`, check `Analyze (javascript-typescript)`) runs CodeQL on `javascript-typescript` with `build-mode: none` for pull requests to `main`, pushes to `main`, and a weekly schedule; it needs no install step. Pull-request CI does not fetch the production URL.
- Pages: the Pages site uses **GitHub Actions** as the Pages source (not “Deploy from a branch”). Live bytes come from orphan branch `gh-pages` via `.github/workflows/deploy-gh-pages-branch.yml` (`workflow_dispatch` on `main`: checkout `gh-pages` only, upload artifact, `deploy-pages`; no build). `publish-gh-pages-production.yml` and `deploy-feature-preview.yml` push `gh-pages` then dispatch that workflow (a token push does not deploy). `.github/workflows/deploy-pages.yml` is **rollback only** (`workflow_dispatch`): rebuilds production and `prototype/` from git. Seed and layout: [intent/feature-previews/plan.md](intent/feature-previews/plan.md). `prototype/` on `gh-pages` is copied once at seed; no workflow republishes it. `publish-gh-pages-production.yml` updates only production root on `gh-pages`. `deploy-feature-preview.yml` publishes `feat/<12-char-sha>/` and PR redirect pointers. Storage keys and tags per `intent/feature-previews/spec.md`. Pushes to `gh-pages` do not run `test.yml`.

## Conventions

- Docs follow the solo AI-native SDLC chain: `intent/<change>/intent.md` → `spec.md` → `plan.md`. Update `plan.md` in the same commit when implementation departs from it.
- The calculator has no npm dependencies. The page's dependencies live in `apps/web` and are installed with pnpm. Do not add a dependency to the calculator or to the `node --test` job.
- The human summary formats money in US locale with two decimal places, from integer cents. `--json` reports money as integer cents. The `--schedule` CSV money columns stay two decimal places with no grouping separators. In ARM mode the CSV adds `rate`, `payment`, and `index`: `payment` is money like the others, while `rate` and `index` print from thousandths with trailing zeros removed (`5.875`, `6.92`, `10.875`), never as two decimals, and `index` is empty when none was given.
- The note rate is percent per year (`6.99` means 6.99%), and the monthly rate is that percent divided by 12.
- There is no default loan. A missing or invalid `--amount`, `--rate`, or term flag exits non-zero and explains the reason on stderr. Exactly one of `--years` or `--months` is required; both or neither fails. No arguments names `--amount`, `--rate`, `--years`, and `--months`. `--json` always includes `months`; `years` appears only when `--years` was passed.

## Architecture

- `amortize.js` is the pure walk. It exports `buildReport(principal, ratePercent, monthCount, extrasByMonth, yearsForJson, arm)`, `dollarsToCents`, `formatGroupedCents`, `formatPlainCents`, `levelArmExtras`, `recastFixed`, `savedByExtraCents`, `savedByExtraByMonth`, `modalPaymentCents`, and `prevailingExtraCents`. The sixth argument `arm` is optional: when it is `undefined` the function is the fixed-rate walk and the report has no `arm` key and no added row fields. When it is the ARM terms object (`fixedMonths`, `adjustMonths`, `marginThousandths`, `initialCapThousandths`, `periodicCapThousandths`, `lifetimeCapThousandths`, `floorThousandths`, `initialFloorThousandths`, `roundEighth`, `indexByMonth` as a `Map` of payment number to index thousandths, and optional `adjustmentStats`), the report gains `arm` (`adjustments`, `max_rate_*`, `max_payment_*`, `ceiling_percent`, and when `adjustmentStats` is present `first_adjustment`, `even_out_cents`, `monthly_extra_cents`) and each schedule row gains `rate_percent`, `payment_cents`, and `index_percent`. It has no Node APIs. `buildReport` always includes `schedule`. `years` is set on the report only when `yearsForJson` is passed. The page calls this module; it does not keep a second formula.
- `calendar.js` exports `paymentDate`, `dueDate`, `yearsAndMonths`, and `formatPayoffDate` with no Node APIs. The page still carries its own copies until it imports this module.
- `picture.js` exports property-tax, insurance, PMI, prepaid-interest, and closing-cost cents helpers, including `buildPictureLines`, with no Node APIs. It may call `buildReport` and `calendar.js`. The page still carries its own copies until it imports this module.
- `compound_interest_monthly.js` is the calculator CLI. It requires `amortize.js`, `calendar.js`, and `picture.js`, parses arguments (including `--level`, `--recast-month`, `--funding`, `--prevailing`, picture flags, ARM flags, and the `--index` CSV), reads `--extra`, and prints. A library `Error` from an ARM term becomes the non-zero exit with the library's message on stderr. It walks a 30/360 schedule, applies extra principal after that month's interest, and stops charging at payoff. The reported schedule still runs through the no-extra payoff; later rows are zeros. `--json` omits `schedule` unless `--schedule` is set. The CSV and `--json --schedule` add `saved_by_extra` / `saved_by_extra_cents`; `--funding` adds accrual columns.
- `fixtures/first-year-100.csv` is the $100-for-the-first-year example.
- `compound_interest_monthly.test.js` is the `node --test` suite.
- `.agents/skills/mortgage-loan-calculator/SKILL.md` is the front end. It asks for a missing principal, note rate, term, or extra plan, writes a `month,extra` CSV, and answers from `--json`. A month or savings-so-far question adds `--schedule` and reads `schedule`. For an ARM it also asks for the initial period, adjustment interval, margin, three caps, and lifetime floor (the first-adjustment floor is optional), runs the worst case when no index is given, writes a `month,index` CSV at adjustment months only for an index path, and reads `arm.max_rate_percent`, `arm.max_payment_cents`, `arm.max_payment_month`, `arm.adjustments`, `arm.floor_percent`, `arm.ceiling_percent`, `arm.first_adjustment`, `arm.even_out_cents`, and `arm.monthly_extra_cents` from `--json`. It does not amortize the loan itself and does not solve the even-out extra.
- `.agents/skills/arm-loan-concepts/SKILL.md` explains the fixed-then-adjusting ARM adjustment procedure in words, and explains ARM types on two axes in its Types section. It has no script, does not compute a payment or rate for a person's loan, and treats the Example Credit Union parameter table as one invented example, not defaults. Design: `intent/arm-concepts/`. Cited consumer answers are in `docs/kb/`. The skill links to those files and does not absorb them. The page shows that Types section from this file and does not rewrite it.
- `intent/mortgage-skill/` is the spec and plan for that skill.
- `intent/arm-loan/` is the spec and plan for the fixed-then-adjusting ARM in the library, the CLI, the skill, and the page. Where `intent/mortgage-skill/` and `intent/loan-recast/` refuse an adjustable-rate loan, `intent/arm-loan/` wins for the ARM it describes. A recast of an ARM through the skill is still declined: the two-run procedure is for a fixed rate.
- `origination_fees.js` is the prepaid-finance-charge CLI. It uses `dollarsToCents` from `amortize.js` and does not walk a schedule. The payment is the note-rate payment. The amount financed is the present value of that payment at the APR. The charge is the note amount minus the amount financed, rounded once at output. `intent/origination-fees/` is the spec and plan. `.agents/skills/mortgage-origination-fees/SKILL.md` is the front end.
- `apps/web` is the amortization page. It imports `buildReport` and `formatGroupedCents` from `amortize.js`. A term in years is `monthCount = years * 12`, passed with the year count as `yearsForJson`. The extra column is the requested dollars; Apply replaces that map. Saved by extra is the marginal lifetime interest that month's requested extra saves given the rest of the committed map: `loanReport` without that month minus `loanReport` on the full map, using each run's `interest_cents`. It is not the row's cumulative `interest_saved_cents`. The column follows the committed map only; an uncommitted extra keystroke does not change it. The page stores more than one loan scenario. Production and the prototype share `STORAGE_KEY`. A version-1 object in that legacy key loads as the first scenario and is not wiped; that key stays version 1 and holds only the active scenario so the prototype and a rolled-back production build still read it. The full set lives in the set key: when the legacy key ends in `-v1`, the set key is the same string with that suffix replaced by `-v2` (the production set key, or the preview key with `-v1` replaced by `-v2`); otherwise the legacy key plus `-scenarios`. A corrupt or unreadable set key loads the legacy loan as the only scenario and is not written until the user edits. When both keys are valid and the legacy loan differs from the active scenario, only the active scenario is replaced (a prototype or rolled-back production edit). `saveStored` writes the whole set to the set key and the active scenario to the legacy key; if either write fails, both keys are restored to the last complete pair and the page shows `Could not save this loan.` under the scenario row. There is no cross-tab sync. Feature preview builds set `VITE_STORAGE_KEY` to the repository name plus `-amortization-feat-<pull-request-number>-v1` so previews do not read or write production storage and open features do not share one loan. A fresh visit is the Conventional loan: purchase price $600,000, 5% down, 30 years, note rate 7.375%. The heading is `{thousands}K | {down}% down | {rate}% fixed = ${whole dollars} / month`. On that visit the heading prevailing monthly payment is $4,853 and the summary principal and interest is $3,936.85. The list at the top switches scenarios, scrolls, adds one with `+`, and removes one from a trash icon after a focus-trapped confirmation except the last. Export and import use the version-2 document (`compound-loan-scenarios.json`); import writes immediately, and a bad or unreadable file keeps the set and shows `This file is not a saved set of loan scenarios.` The heading dollar is the prevailing monthly total (modal principal and interest, plus picture taxes, insurance, PMI, and MIP, plus the prevailing extra) in whole dollars. The `#scenario` label is the 1-based list number, a colon, a space, then that amount, a hyphen, thousands, down percent, the note rate, the parsed term, and `fixed` or the ARM structure. A fresh visit shows `1: $4,853 - 600K | 5% down | 7.375% | 30 years | fixed`. The open menu uses the same prefix. In fixed mode the Monthly payment block has no note; the ARM block keeps `Initial payment. The extra payment is on top of this amount, and the payment resets at each adjustment.` When the extra map has any amount the summary shows `Extra principal paid` (the report's `extra_applied_cents`, the applied total, not the requested one) immediately before Interest saved. Payoff date is the due date `{Month} 1, {year} ({yearsAndMonths(payoff_month)})` (`November 1, 2056 (30 years)` on the fresh Conventional loan), with a payoff footnote and a schedule footnote that payments are made in arrears; schedule rows stay accrual months (`paymentDate`, not `dueDate` on rows), and Months saved is the bare count under twelve and years and months from twelve (`2 years 4 months`), both from `yearsAndMonths` in `loan.ts`. Moving in is a disclosure after Closing Costs. It reads the funding date from the start month and the closing day, and an interest credit does not relabel schedule rows. The start month is a page-drawn picker, not an `<input type="month">`: `button#start` shows the long date (`October 2026`) with `data-value="YYYY-MM"`, `aria-haspopup="dialog"`, and `aria-expanded`; it opens a `Choose start month` dialog with `Previous year` / `Next year` (years 1000-9999) and twelve month buttons named `{Month} {year}` (`aria-pressed` on the current one). Choosing a month commits through `update("start", …)`, closes, and refocuses the trigger; Escape and a pointer down outside the card, trigger, and its label close it; the label click toggles it. The chart legend is a tooltip: `position: fixed`, `pointer-events: none`, placed from an anchor in viewport coordinates (the pointer's `clientX`/`clientY` for a mouse move or a touch tap; for the keyboard, the indicated bar's center x and the chart's top edge) with its own measured size, a 16px gap, and an 8px window margin. It sits right of and below the anchor, flips to the left or above when it would leave the window, and is clamped otherwise, so it may leave the chart's box and may cover the anchor only when neither side fits. Because it takes no pointer events, the month under the pointer is always the indicated month. Make extra payments and Monthly payment and closing costs open from disclosure summaries. Closing Costs is lender fees (default $3,000 on a fresh visit), title escrow and recording as a percent of price with presets 50/50 at 0.75%, buyer-pays-all at 1.00%, and seller pays owner policy and escrow at 0.40%, prepaid interest from the start month (the closing month) with `#picture-closing-day` and `#picture-interest-basis` (`360` default, `365` optional), a twelve-month homeowners insurance line, three impound month counts, property-tax proration, then Closing costs (points excluded; the reference fixture is $16,572.41 clean), Points, Closing costs and points, seller credit, lender credit, Cash to close, earnest money, and Due at closing. There is no percentage origination fee. A stored origination percent and processing fee map once to lender-fee dollars. Proration is omitted from storage until the owner edits it. Apply sits in a `.apply-row` beside the sentence `Apply rewrites all extra-payment column values.`, which appears once; the old line above the form is gone. On an ARM, `#extra-level` (`Match the initial-period total after each reset`) sits after the monthly, yearly, and month-of-year fields and before that Apply row, defaulting off. Apply with it on writes `levelArmExtras`, which calls `buildReport` once per adjustment period after earlier extras are in the map and does not modify `amortize.js`. When the last Apply stored `appliedLevel` and no extra cell differs from `applied`, an index commit replaces both extra maps from that reset through the term, including later periods whose index did not change, and deletes zero extras. Inside `.field` a `select` has `appearance: none`, the inputs' font size, padding, and line height, and a data-URI chevron so its border and baseline line up with the amount fields in Safari; `#product` is excluded and keeps its native arrow. An extra cell is `data-edited="true"` (blue, `--edited` `#1d4ed8`, on the text and the bottom border) when its committed amount differs from the stored `applied` map for that month, which is the requested-extra map as the last Apply wrote it. Apply sets `applied` to the new map, so no cell is edited after it; a commit changes the attribute and a keystroke never does. `applied` is saved beside `extras` as `[[month, dollars], …]`; a missing or malformed key is read as equal to the loaded `extras`, and a term change drops months past the term from both. The year row's Saved by extra is the sum of that year's cells (`$0.00` with no extra), and the subtotals do not add up to Interest saved: on $100 in months 1–12 the year rows sum to `$8,071.88` while Interest saved is `$8,137.70`. Picture principal and interest is `monthly_payment_cents` from `buildReport` on the financed principal. After Total monthly payment the picture adds Prevailing principal and interest (`modalPaymentCents` from `scenarioFigures`; on an ARM that is the applied-map report's `monthly_payment_cents`, the initial-period payment, and a fixed-rate loan still uses its one scheduled payment through `payoff_month`; the Highest payment line stays the schedule walk's `arm.max_payment_cents`), Prevailing extra, and Prevailing monthly total. The prevailing-extra bar segments use green `#1b7a4d` (PI), navy `#2a4365` (TI), and gold `#8a6218` (PE); a zero share is omitted; `column-gap: 1px` on the bar shows `var(--paper)` between segments; the legend after `.heading-line` reads `PI`, `TI`, and `PE`. The heading bar is a sibling after `span.complete-payment`, not inside it. Prevailing extra is the applied-map report's `extra_cents` on months 1 through `n`, grouped by amount: a positive amount counts only when `c * 5 >= n * 4`, where `n` is not the parsed contract term. On an ARM report, `n` is the lesser of `payoff_month` and `arm.fixed_months`. A fixed-rate loan still uses `payoff_month`, and its rows are `1 .. payoff_month`. Fixed mode has eight schedule columns: `#`, Date, Principal, Interest, Extra payment, Saved by extra, Principal balance, Interest balance. ARM mode has eleven, with Index still before Extra payment. The schedule has no Prevailing extra column. Extra payment is each month's requested amount. The prevailing extra stays on the summary bar. The prototype stays at `prototype/` on the Pages site. Vite's `base` defaults to `./`. Atkinson Hyperlegible and IBM Plex Mono live in `apps/web/fonts` with their SIL Open Font License files; the build fails, and names the file, if a shipped font's license is not that license.
- The page has an ARM mode (`apps/web/src/arm.ts`). The heading's static `fixed` is a `<select id="product">` with `fixed` and `ARM`; in ARM mode a structure label (`7/1` for 12 months, `7/6` for 6, otherwise `{years}/{months}mo`, so a 1-month interval is `7/1mo`) sits before the select. The current index is not the schedule Index column and is not passed to `buildReport` or `indexByMonth`. A fresh visit and every saved scenario without a well-formed `arm` object are `fixed`. When the product is ARM, the ARM terms disclosure sits directly under the heading line and loan field error and above Taxes and Insurance. The change-date line states that the payment due that day is still the previous amount. The first switch opens it and stores `open: true`; after that the stored flag wins. ARM figures on the page are `buildReport` with the sixth `arm` argument: `loanReport` and `savedByExtraCents` pass it only while the product is ARM and pass `undefined` when it is `fixed`, even though the terms and the index stay in storage under `arm` (`enabled: false`). The `arm` key is written only once the owner has selected ARM or toggled the disclosure. The summary gains "Highest rate" (`from {long date}` only) and "Highest payment" (`from {long date} · first due {Month} 1, {year}`) in ARM mode only, and the Monthly payment note reads "Initial payment. The picture's Principal and interest row stays `monthly_payment_cents`, the initial payment; the heading dollar is the prevailing monthly total. An invalid term entry names the field and keeps the last valid terms; a floor of 0 or above `rate + lifetime cap`, an initial period not shorter than the term, and a rate edit that drops the ceiling under a floor are field errors, never a library throw. Switching to ARM with stored terms that no longer fit the loan is refused with that field error. In ARM mode the schedule has eleven columns: `#`, Date, Rate, Payment, Principal, Interest, Index, Extra payment, Saved by extra, Principal balance, Interest balance (the ten-column header is the CLI's CSV, not the table); fixed mode has eight and also has no Prevailing extra column. Saved by extra on an ARM runs `buildReport` with the same `arm` object on both runs. The table still ends at `payoff_month`.

## Things agents get wrong

- Do not put the $855,000 / 6.99% / 30-year gist loan back as constants that run when arguments are missing. That scenario is only `--amount 855000 --rate 6.99 --years 30`.
- Charging stops when the principal reaches zero. Do not keep accruing interest after payoff. The schedule still lists the later months through the no-extra payoff, with zeros, so the last `interest_saved` matches the summary.
- `Extra principal paid` is `extra_applied_cents`, the dollars that reduced principal. $100 on every month of the $570,000 / 7% / 30-year loan is `$33,200.00` (the loan is gone in month 332), not `$36,000.00`.
- Do not put `<input type="month">` back for the start month: Safari and Firefox render it as a text field. The picker is page-drawn so every browser sees one control.
- Do not make the Saved by extra year subtotals sum to Interest saved, and do not mark an extra cell edited on a keystroke: it is edited only when the committed map differs from `applied`.
- An extra payment does not reduce that month's interest. On $570,000 at 7%, month 1 interest is 332500 cents even when month 1 includes extra principal. Interest saved is cumulative against the no-extra schedule, so that same example saves 0 cents in month 1 and 813770 cents by month 360. Saved by extra, when the column exists, is a different number: the lifetime interest that one month's extra saves given the rest of the map. Do not fill it with `interest_saved_cents`.
- The skill asks when the principal, note rate, term, extra plan, or recast month is missing. It does not invent taxes, insurance, or an $855,000 loan. Summary questions use `--json` alone. A month or savings-so-far question is the only reason to add `--schedule` on a non-recast run. A recast passes `--recast-month` and reads `recast.monthly_payment_cents`. An APR fee, points, or lender-credit question is `origination_fees.js`, not this script.
