## 1. Summary

Shared loan formulas move into pure modules the calculator command-line tool and, in a later phase, the amortization page both call. The tool runs one loan. It can level ARM extras, recast a fixed-rate loan, print both savings figures on a schedule, report prevailing principal and interest and prevailing extra, format dates from a funding month, and price property tax, insurance, PMI, and closing costs when those inputs are passed. The page then calls the same functions, gains a term and an ARM initial period in months, and gains a fixed-rate recast control. `apps/web/package.json` stays `0.22.0` until that page phase, which sets `0.22.1`. Regulation Z APR is not this change.

This folder builds on [intent/arm-extra-level/](../arm-extra-level/spec.md), [intent/loan-recast/](../loan-recast/spec.md), [intent/extra-savings-column/](../extra-savings-column/spec.md), [intent/loan-scenarios/](../loan-scenarios/spec.md), [intent/arm-fixed-period-pe/](../arm-fixed-period-pe/spec.md), [intent/arm-fixed-period-pi/](../arm-fixed-period-pi/spec.md), [intent/clean-closing-costs/](../clean-closing-costs/spec.md), and [intent/mortgage-start-timeline/](../mortgage-start-timeline/spec.md). Where those specs keep level extras, the recast, the picture math, or a year-only page term on the page alone, this spec wins for the functions and the page controls below. The interest walk inside `buildReport` stays the walk those specs already define.

## 2. Goals and non-goals

**Goals**

- G1. One library function levels ARM extras. The command-line tool and the page call it.
- G2. One library function recasts a fixed-rate loan. The command-line tool prints it. The page shows it. An ARM recast is declined.
- G3. A schedule surface shows Interest saved and Saved by extra as two figures.
- G4. Prevailing principal and interest, and prevailing extra, are library functions the command-line tool can print.
- G5. A funding month formats dates on the command-line tool and does not change the interest walk. The page keeps using the same date functions.
- G6. Property tax, home insurance, PMI, and closing costs are library formulas the command-line tool can run when the inputs are passed.
- G7. The page accepts a term in months and an ARM initial period in months.
- G8. The page version moves only in the phase that changes page behavior.

**Non-goals**

- Regulation Z APR, a change to `origination_fees.js`, or a change to the origination-fee skill.
- Interest-only, payment-option, or negative-amortization arithmetic.
- A saved set of scenarios, a chart, or the income-tax table on the command-line tool.
- A new scenario-document version. Storage stays version 2 on the set key and version 1 on the legacy key.
- A Pages deploy, or an edit to `.github/workflows/`.
- A personal-data rule in the repo.
- Inventing a tax, an insurance rate, a PMI rate, a lender fee, or a recast fee the user did not give.

**Release phasing.** Untagged requirements are this release. The library and the command-line tool land before the page calls them. The page version stays `0.22.0` until the page phase.

## 3. Principles

- P1. `buildReport` stays the interest walk. New behavior is a new function that calls it, or a pure cents formula. Reported money is still integer cents, rounded half up once at output.
- P2. Modules the page imports have no Node APIs. The command-line tool is the only place that reads files and `process`.
- P3. A missing picture input is an error on the command-line tool. The page keeps its own defaults. The tool does not copy those defaults in silently.
- P4. Interest saved and Saved by extra keep their names. The sum of Saved by extra is not Interest saved.
- P5. The funding month and the even-out `--start` flag are different inputs. Neither one changes a month's interest.
- P6. The skill runs the tool and reads the JSON. It does not type these formulas.

## 4. Users and scenarios

- The owner asks for the payment after a fixed-rate recast. The skill passes `--recast-month` and reads the recast payment from the JSON. It does not launch a second process for that payment.
- The owner asks what an ARM payment becomes if extras hold the initial-period total. The skill writes the form extras and passes `--level`. It does not solve the extra.
- The owner asks what month 1's extra saves, and what the loan has saved so far. The schedule row has both cents, under both names.
- The owner passes a loan, a price, and a property-tax rate. The tool prints the monthly tax. It does not invent insurance.
- The owner sets the page term to 13 months. The heading says `13 months`. A stored loan that has no term unit is still 30 years.
- The owner types a recast month on a fixed loan. The disclosure shows the new payment. The schedule and the heading payment stay the loan without that recast.
- The owner asks for a recast of an ARM. The skill declines in one sentence. The tool exits non-zero if `--recast-month` is combined with ARM flags.

## 5. Functional requirements

1. **Modules.** `amortize.js` gains the functions in requirements 2–5 and still has no Node APIs. `buildReport`'s return value, when called as it is today, gains no key and no schedule-row field. `calendar.js` holds the date functions in requirement 6. `picture.js` holds the cents formulas in requirement 7 and may call `buildReport` and `calendar.js`. `picture.js` and `calendar.js` have no Node APIs. `amortize.d.ts`, `calendar.d.ts`, and `picture.d.ts` declare the exports the page imports. No package is added. `node --test` collects `amortize.test.js`, `calendar.test.js`, and `picture.test.js`.

2. **Level extras.** `levelArmExtras(principalDollars, ratePercent, monthCount, arm, formExtrasByMonth, fromMonth, keptByMonth)` returns a `Map` of payment month to positive dollars. `arm` is the object `buildReport` already accepts. `adjustmentStats` on it is ignored. `formExtrasByMonth` and `keptByMonth` are maps of month to dollars. The function throws `level extras require an ARM` when `arm` is missing. It implements the rule in `intent/arm-extra-level/` requirement 3, including one `buildReport` per adjustment period after earlier extras are in the map, a zero extra deleted, and no retarget from a zero `payment_cents` after payoff. The fixed-period months from `fromMonth` through the initial period keep the form extra. `fromMonth` is the first month the call may replace. Months before `fromMonth` are copied from `keptByMonth` when the amount is positive. The page's `levelArmExtras` becomes a wrapper: it builds the form map with `buildPrefillMap`, converts the financed principal to dollars, and calls this function. The checkbox label stays `Match the initial-period total after each reset`. The command-line flag `--level` requires ARM mode, uses `--extra` as the form map (an omitted file is an empty map), and calls the function with `fromMonth` 1 and an empty kept map before `buildReport`. `--level` without ARM mode exits non-zero and prints `level extras require an ARM`. The fixtures F2 through F6 in `intent/arm-extra-level/` requirement 8 still hold.

3. **Fixed-rate recast.** `recastFixed(principalDollars, ratePercent, monthCount, extrasByMonth, recastMonth)` walks the loan, then walks the remaining principal at that month over `monthCount - recastMonth` at the same rate with no extras. The second principal is `formatPlainCents` of that row's `remaining_principal_cents`, parsed as dollars, so the second `amount_cents` equals the row. The return value is `{ recast_month, remaining_principal_cents, months, monthly_payment_cents, interest_cents, payoff_month, interest_through_cents, lifetime_interest_cents }`. `interest_through_cents` is the sum of `interest_cents` on schedule rows 1 through the recast month. `lifetime_interest_cents` is that sum plus the second walk's `interest_cents`. A recast month that is not an integer from 1 through `monthCount - 1` throws `recast month must leave a positive remaining term`. A row whose `remaining_principal_cents` is 0 throws `loan is already paid off at the recast month`. The sample in `intent/loan-recast/` requirement 8 returns `remaining_principal_cents` 45361449, `months` 336, `monthly_payment_cents` 319568, `interest_cents` 62013361, `payoff_month` 336, `interest_through_cents` 7569885, and `lifetime_interest_cents` 69583246. Checked 2026-10-31 by summing the first walk's printed `interest_cents` on rows 1–24 and adding the second walk's `interest_cents`. `--recast-month` on the command-line tool calls this function. The JSON gains a `recast` object with those fields. The human summary keeps its existing lines and appends these lines, in this order. Money lines use `formatGroupedCents`. The two month counts are plain integers.

```
Recast month: 24
Recast principal: 453,614.49
Recast payment: 3,195.68
Recast months: 336
Recast interest: 620,133.61
Interest through recast: 75,698.85
Lifetime interest with recast: 695,832.46
``` ARM flags together with `--recast-month` exit non-zero with `a recast is for a fixed rate` and do not call the function. The skill uses this one run. It reads `recast.monthly_payment_cents` as the payment and `recast.interest_cents` as the interest if only that payment is made. It reads `recast.interest_through_cents` and `recast.lifetime_interest_cents` when the question asks for those sums. It does not add the cents itself. A question about extra principal after the recast is still a further run of the remaining loan. An ARM recast is still declined in one sentence: the recast is for a fixed rate, and an ARM already re-amortizes at each reset.

4. **Both savings figures.** `savedByExtraCents(principalDollars, ratePercent, monthCount, extrasByMonth, month, fullInterestCents, arm)` is the page's marginal figure: 0 when that month's extra is not positive, otherwise the interest of the same loan with that month removed, minus `fullInterestCents`. `arm` is omitted for a fixed loan. `savedByExtraByMonth` returns an array of length `monthCount`, index 0 for payment month 1, one cent per schedule row through the contract term the CSV already prints, including a zero row after payoff. `buildReport` does not grow a `saved_by_extra_cents` field. The command-line CSV inserts `saved_by_extra` immediately after `interest_saved`, on a fixed loan and on an ARM. `--json --schedule` adds `saved_by_extra_cents` on each row. The human summary does not gain a Saved by extra total. On $570,000 at 7% for 30 years with $100 in months 1–12, month 1 is 69761, month 12 is 64818, month 13 is 0, the sum of the column is 807188, and the last row's `interest_saved_cents` is 813770. On the ARM in `intent/arm-loan/` with $100 in months 1–12, month 1 is 30907 and month 13 is 0, and `interest_saved_cents` is 357936. The page's `savedByExtraCents` calls the library function. This requirement wins over the byte-identical fixed-rate CSV and the byte-identical `--json --schedule` output in `intent/arm-loan/`. The human summary, and `--json` without `--schedule`, stay byte-identical for `--amount 570000 --rate 7 --years 30`: summary sha256 `adc8f5d8b2e6695d469ad69923bc4ef46ef2b4677a58c89fc57fd02c8d540ad5`, JSON sha256 `7c59cdf637313c70c13a5735b1ef6c6f365e8a260ac311df4eee2ecb6bb45108`. A fixed run still has no `arm` key and no `rate_percent` on a row.

5. **Prevailing principal and interest, and prevailing extra.** `modalPaymentCents(report)` and `prevailingExtraCents(report)` move as they are written in `apps/web/src/loan.ts` on 2026-10-31. Prevailing principal and interest is the initial `monthly_payment_cents` on an ARM and the scheduled `monthly_payment_cents` on a fixed loan. Prevailing extra uses `payoff_month` on a fixed loan and the lesser of `payoff_month` and `arm.fixed_months` on an ARM, and the test `count * 5 >= months * 4`. The page calls these functions. The command-line tool prints them only when `--prevailing` is set or a picture flag from requirement 7 is set. The JSON then gains `prevailing`: `{ principal_and_interest_cents, extra_cents }`. The summary appends `Prevailing principal and interest` and `Prevailing extra`. Those keys are absent on a run that does not ask for them.

6. **Funding month.** `calendar.js` exports `paymentDate`, `dueDate`, `yearsAndMonths`, and `formatPayoffDate` with the behavior `apps/web/src/loan.ts` has on 2026-10-31. Payment 1 is the calendar month after the funding month. The payoff date is the due date of `payoff_month`, the 1st of the following month, then the `yearsAndMonths` duration. `--funding YYYY-MM` on the command-line tool is that month. It is not an ARM flag. It does not change payment, interest, payoff month, or extra cents. The existing `--start` flag stays the even-out month (`1` through `12`, or `YYYY-MM` reduced to that month) and still turns ARM mode on, as it does today. When `--funding` is set, the summary appends `Payoff date: ` plus `formatPayoffDate`, and one arrears line: `Payments are made in arrears: each month's row is the accrual month, paid on the 1st of the following month.` The JSON `payoff_date` is `formatPayoffDate` alone, without the `Payoff date: ` label. The CSV inserts `accrual` after `month`, as `YYYY-MM`. `--json --schedule` adds `accrual_month` (`YYYY-MM`) and `due_date` (`YYYY-MM-DD`, the 1st). An invalid `--funding` exits non-zero and names the flag. A positive `--even-yearly` still requires `--even-month`. It also requires a calendar month: `--start` when that flag is present, otherwise the calendar month of `--funding` (`2026-10` supplies 10, the same month `parseStartMonth` keeps). When both flags are present, `--start` is the even-out month and `--funding` is only the date anchor. When `--even-yearly` is positive and both are absent, stderr stays `missing required argument: --start`. The page's date helpers call `calendar.js`. The schedule rows stay accrual months.

7. **Picture formulas.** `picture.js` exports the cents math now in `apps/web/src/picture.ts`: `percentOfCents`, `titleCentsFromPrice`, the 360 and 365 prepaid-interest functions, `closingInterestDays` and the month-length helpers it uses, `pmiThousandthsForScore` with the ladder already in that file (780+ is 200 / 350 / 450 thousandths, not a 760+ column), and `buildPictureLines`. `buildPictureLines` takes integer inputs and returns the line cents the page's `buildPicture` returns, including principal and interest from `buildReport` on the financed principal for the loan's `monthCount`. Points stay outside closing costs. The 365 charge stays per-diem cents times days. Called with the integer inputs in `intent/clean-closing-costs/` requirement 11, `buildPictureLines` returns closing costs of 1657241 cents. That check is the function call. The page's `buildPicture` calls `buildPictureLines` and keeps parsing, defaults, storage, and the FICO labels. The income-tax table stays in `apps/web/src/tax.ts` and uses the loan's `monthCount` for its term length.

   `--amount`, `--rate`, and exactly one of `--years` or `--months` stay required on every run. A picture flag does not replace them and does not turn on ARM mode. The command-line tool accepts, when passed: `--price`, `--down-percent`, `--tax`, `--insurance`, `--pmi`, `--fico`, `--prevailing`, and `--closing` with `--closing-day`, `--interest-basis`, `--lender-fees`, `--title`, `--homeowners`, `--tax-impound-months`, `--insurance-impound-months`, `--mi-impound-months`, `--proration`, `--points`, `--seller-credit`, `--lender-credit`, and `--earnest`.

   Units. `--price` is dollars greater than zero, the same grammar as `--amount`. `--lender-fees`, `--seller-credit`, `--lender-credit`, and `--earnest` are dollars greater than or equal to zero. `--proration` is dollars and may be negative. `--homeowners` is the twelve-month insurance premium in dollars, greater than or equal to zero. `--tax`, `--insurance`, and `--pmi` are percents with at most three decimal places. `--points` is a percent of the loan, at most three decimal places, 0 inclusive and less than 100. `--title` is a percent of price with at most five decimal places. `--down-percent` is a percent greater than or equal to zero and less than 100, at most three decimal places. `--fico` is an integer from 0 through 999. `--closing-day` is an integer from 1 through 31, then clamped to the funding month. `--interest-basis` is `360` or `365`. Each impound count is an integer from 0 through 999.

   Housing lines. `--tax` and `--insurance` are annual percents of price and require `--price`. The monthly cents are `percentOfCents(priceCents, thousandths, 12)`. `--pmi` is an annual percent of the loan amount; the monthly cents are `percentOfCents(loanCents, thousandths, 12)`. `--fico` uses the ladder and requires a down percent, from `--down-percent` or from `--price` minus `--amount`. Both `--pmi` and `--fico` is an error that names both flags. `--price`, `--amount`, and `--down-percent` together must agree to the cent. A picture flag without a required companion exits non-zero, names the missing flag, and prints nothing on stdout.

   JSON and summary for a requested housing line. Keys are absent when that line was not requested. They are not printed as zero.

   | Request | Summary line | JSON |
   |---|---|---|
   | `--tax` | `Property tax: ` plus `formatGroupedCents` | `picture.property_tax_cents` |
   | `--insurance` | `Home insurance: ` plus `formatGroupedCents` | `picture.insurance_cents` |
   | `--pmi` or `--fico` | `Mortgage insurance: ` plus `formatGroupedCents` | `picture.pmi_cents`. `--fico` also sets `picture.pmi_thousandths` |
   | `--prevailing`, or any housing or closing flag | `Prevailing principal and interest: ` and `Prevailing extra: ` | `prevailing.principal_and_interest_cents` and `prevailing.extra_cents` |
   | any housing line or `--closing` | `Prevailing monthly total: ` | `picture.prevailing_total_cents`, the sum of prevailing principal and interest, the housing lines that were requested, and prevailing extra |

   Closing. `--closing` requires `--funding`, `--price`, `--closing-day`, `--interest-basis`, `--lender-fees`, `--title`, `--tax`, the three impound counts, `--proration`, `--points`, `--seller-credit`, `--lender-credit`, `--earnest`, a PMI choice (`--pmi` or `--fico`), and an annual insurance line. The annual line is `--homeowners` when that flag is present, and otherwise `percentOfCents(priceCents, insuranceThousandths)` from `--insurance`. `--closing` therefore requires `--insurance` only when `--homeowners` is omitted. Both flags may be passed together: `--homeowners` is the twelve-month line and the insurance impound base (`halfUp(annualCents, 12)` times the impound months), and `--insurance` is only the monthly housing line. The JSON object `closing` has `lender_fees_cents`, `title_cents`, `prepaid_interest_cents`, `prepaid_interest_days`, `homeowners_insurance_cents`, `tax_impound_cents`, `insurance_impound_cents`, `mi_impound_cents`, `proration_cents`, `closing_cents`, `points_cents`, `closing_and_points_cents`, `cash_to_close_cents`, and `due_at_closing_cents`. Points are not inside `closing_cents`. The summary uses those labels: `Lender fees`, `Title, escrow, and recording`, `Prepaid interest`, `Homeowners insurance`, `Property tax impound`, `Insurance impound`, `Mortgage insurance impound`, `Proration`, `Closing costs`, `Points`, `Closing costs and points`, `Seller credit`, `Lender credit`, `Cash to close`, `Earnest money`, `Due at closing`. The seller-credit sentence the page already shows is one more summary line when that condition is true, and the command still exits 0.

8. **Page term and initial period in months.** The heading keeps `#years` and the suffix that makes the fresh-visit heading text `30-year`. `#term-unit` (accessible name `Term unit`) replaces that literal suffix. Its selected option text is `year` or `month`, so the years-mode heading string stays `600K | 5% down | 7.375% 30-year fixed | 780+ | starting October 2026` on the clock the page tests already use, and a 13-month term reads `13-month` in that same position. `#years` is the visible amount when the unit is years. `#months` is the visible amount when the unit is months. The other input is not rendered. Each stored string keeps its own text. Switching the unit does not copy or multiply the number. An empty or invalid amount for the selected unit is a field error (`Term must be a positive whole number of years.` or `Term must be a positive whole number of months.`) and keeps the last valid loan. `LoanDraft` gains `termUnit` and `months`. A missing or non-string `termUnit` loads as `years`. A missing or non-string `months` loads as `""`. The parsed `Loan` has `monthCount` and `termYears`. `termYears` is set only when the unit is years. `monthCount` is `termYears * 12` or the months integer. There is no parsed `years` that still holds 30 while the unit is months. `buildReport` receives `yearsForJson` only when `termYears` is set. Every page amortization uses `monthCount`: `loanReport`, the level-extra wrapper, `buildPicture`, ARM reset months, dropping extras past the term, `parseArm`'s comparison, and the term length inside `tax.ts`. The scenario label uses `1 year` / `N years` or `1 month` / `N months`. The ARM disclosure shows `#arm-fixed-years` when the unit is years and `#arm-fixed-months` when it is months. `#arm-fixed-unit` (accessible name `Initial period unit`) has selected text `years` or `months`. An empty or invalid amount for the selected unit uses `Initial period must be a positive whole number of years.` or `Initial period must be a positive whole number of months.` and keeps the last valid terms. `fixedYears` stays the year text. The month text is stored as `initialMonths`, default `""`. A missing or non-string `fixedUnit` loads as `years` and does not reject a stored ARM. A missing or non-string `initialMonths` loads as `""`. The initial period in months must be shorter than the term in months, with the existing sentence `Initial period must be shorter than the term.` `armLabel(fixedMonths, adjustMonths)` uses the month counts. When `fixedMonths` is divisible by 12, the year count is `fixedMonths / 12`: a 12-month interval is `{years}/1`, a 6-month interval is `{years}/6`, and any other interval is `{years}/{adjustMonths}mo` (so 84 and 1 is `7/1mo`). When `fixedMonths` is not divisible by 12, the label is `{fixedMonths}mo/{adjustMonths}mo`. The fresh visit is unchanged: 30 in `#years`, initial period 7 years, heading text `30-year`, structure `7/1`. The scenario document stays version 2. The legacy key stays version 1. The stored `years` string remains, so a reader that ignores `termUnit` still sees the year text.

9. **Page recast control.** A fixed loan shows a `Recast` disclosure immediately after Extra Payments and before the schedule. `#recast-month` takes a payment number. Empty shows no figures. A month outside 1 through `monthCount - 1` is a field error and keeps the last valid entry. A month whose remaining principal is 0 shows `The loan is already paid off.` and no payment. A valid month shows the unpaid principal, the recast payment, the remaining months, and the recast interest, from `recastFixed` on the applied extra map and the financed principal. The schedule, the heading dollar, and the monthly payment do not change. An ARM does not render the disclosure. `recastMonth` is a string on the scenario, default `""`. A missing or non-string value loads as `""`. The set key stays version 2.

10. **Version, docs, and what stays.** Phases that do not change page behavior leave `apps/web/package.json` at `0.22.0`. The page phase sets `0.22.1`. `PAGES_POINT_VERSION` is derived from that version as major.minor, so it stays `0.22`. The workflow file is not edited. No Pages workflow is dispatched. `AGENTS.md` and `README.md` gain the flags, the new modules, the page controls, and the version sentence in the phase that lands them. `REVIEW.md` names `intent/library-cli-parity/`. Things agents get wrong gains: do not fold Saved by extra into Interest saved; do not add `saved_by_extra_cents` inside `buildReport`; do not treat `--start` as the funding month; do not let `--funding` change the interest walk; do not invent a picture rate on the command-line tool; do not recast an ARM; do not bump the scenario document to version 3; do not set the page version to `0.23` for this change; do not dispatch a Pages deploy. The same edit retires the older sentences that forbid a prevailing-extra command-line flag and that forbid any new column on a fixed-rate schedule: this spec adds `--prevailing` and the `saved_by_extra` column, and the fixed-rate summary and the JSON without a schedule stay byte-identical. The teaser indicator, the knowledge panel, and the current-index field stay as `intent/teaser-indicator/` left them.

## 7. Design decisions

**D1 — Three modules, and `buildReport` stays the walk.** Level extras, the recast, Saved by extra, and the two prevailing figures need the walk, so they live in `amortize.js`. Dates and picture cents do not, so they live in `calendar.js` and `picture.js`. Putting dates inside `buildReport` was rejected because the funding month must not change interest. Adding `saved_by_extra_cents` on the walk's own rows was rejected because the fixed-rate object comparison would fail. Checked 2026-10-31: `buildReport` is exported from `amortize.js` with no Node APIs, and the page imports that file by name.

**D2 — The default summary and the JSON without a schedule stay byte-identical.** The schedule is the surface that gains Saved by extra, an accrual column, and a recast object only when those flags are present. Checked 2026-10-31: the summary sha256 and the no-schedule JSON sha256 for `$570,000` at 7% for 30 years are the digests in requirement 4. The CSV sha256 `d3129f7e97827934a05d350a599c3b375c2296a604ca0ec076ff2c3920cea620` and the scheduled JSON sha256 `8a214dc5815a70c16721113f23c186b90340d7ec633c017209f1915860819292` are the pre-change pins and are not the targets after this requirement.

**D3 — `--funding` is a new flag. `--start` stays the even-out month.** `--start` is already an ARM-mode flag and stores only a month number. Reusing it as the loan's funding month would turn a fixed-rate date request into an ARM parse, or would drop the year. A positive even-out yearly amount still needs a calendar month. `--funding` supplies that month only when `--start` is absent, and the month is the `YYYY-MM` month number. Checked 2026-10-31: `parseStartMonth` returns 1 through 12, and `ARM_FLAGS` includes `start`.

**D4 — The command-line tool does not invent picture inputs.** The page defaults ($3,000 lender fees, 1.15% tax, 0.35% insurance, the 780+ PMI ladder) are page defaults. A tool run without those flags must not quote them. The ladder moves so `--fico` and the page share one table. `--homeowners` is the page's optional annual premium, and it may sit beside `--insurance` the way that premium sits beside the insurance percent. The income-tax table stays on the page because the approved line is tax, insurance, and PMI rates, which are the monthly housing rates. Its term length still follows the loan's `monthCount`.

**D5 — A recast on the page does not replace the schedule.** The schedule remains the loan the owner is amortizing. The disclosure answers the recast question from the applied extras. Applying the recast as a new scenario was rejected because this change does not grow scenario behavior beyond one stored month string.

**D6 — Term units are two stored strings.** `years` stays the year text a reader that ignores `termUnit` already understands. `months` is the other text. Switching the select does not multiply by 12, so a 30-year loan does not become a 360-month loan by accident, and a 13-month loan is not written into `years` where an older reader would treat 13 as years. The scenario document stays version 2 because the approved storage rule forbids version 3. The ARM draft splits the same way: `fixedYears` and `initialMonths`. `initialMonths` is the stored string. It is not the numeric `fixedMonths` the walk already uses. The structure label stays the existing year form whenever the initial period is a whole number of years, so 84 months and a 12-month interval is still `7/1`, and 84 months and a 1-month interval is still `7/1mo`.

**D7 — The page version is 0.22.1.** The approved batch names 0.23 as the Regulation Z APR solver. This change does not start that solver. A behavior change still moves `apps/web/package.json`. The production point version is major.minor of that file, so `0.22.1` keeps the point version at `0.22`. The workflow file stays untouched, and no deploy is dispatched. Checked 2026-10-31: `publish-gh-pages-production.yml` sets `PAGES_POINT_VERSION` from `apps/web/package.json` with a major.minor match, and the teaser release left the package at `0.22.0`.

**D8 — The skill's two-run recast becomes one flag.** `intent/loan-recast/` defined the recast as a second walk and told the skill to launch it. The library now performs that second walk. The skill reads the result. The definition (same rate, remaining term, balance after the recast month, no fee) is unchanged. A later extra on the recast loan is still a separate run, because that question is a different extra plan.
