2. Implement spec requirements 2 through 5 by walking. The worst-case probe uses an empty extra map and an empty index. The minimum probe uses an empty extra map and a present index entry of `0` at `fixedMonths + 1` only, so `resetRate` treats `0` as an index. The even-out search, for each month from 1 through `fixedMonths`, converts the candidate cents once with `Number(`${whole}.${two digits}`)`. A month is omitted only when that cent amount is zero. The comparison is one `dollarsToCents` of the walk row's dollar `payment` (that value is `payment_cents`) against `monthly_payment_cents` plus the candidate. An absent reset compares as 0. **Departure (2026-10-16, owner):** the even-out extra no longer binary-searches `[0, max_change_cents]`. The balance after the fixed period is linear in the monthly extra (yearly lumps at their calendar months are in the base balance). The first-adjustment worst-case payment is that balance times the payment-per-dollar at the actual max rate for that reset. The closed form solves `initial payment + E` equals that payment; clamp `E` so the balance stays non-negative. Then walk only `floor(amount * 100) / 100` and `ceil(amount * 100) / 100` as integer cents and keep the smaller cent that passes; if neither passes, step outward one cent at a time until one passes (no full-range binary search). Payoff before the first adjustment leaves the extra at 0. When `max_change_cents` is 0 or negative, the even-out extra is 0 without the closed form. The yearly monthly-extra solve reuses the same rule. The yearly cents are not added on the comparison side. The yearly cents are not added on that side. When `yearlyExtraCents` is 0, or the yearly month never lands in the fixed period, `monthly_extra_cents` reuses `even_out_cents` and there is no second search. For each month from 1 through the fixed period, the cent sum is `E`, plus `yearlyExtraCents` when the calendar month equals `yearlyMonth`. Convert that sum once with the same string conversion, and store those dollars. Omit the month only when the cent sum is zero. F4 keeps the January months when `E` is 0 and the yearly extra is 2000000 cents. When the yearly month never falls inside the fixed period, the map has no yearly entry and `monthly_extra_cents` equals `even_out_cents`. When `adjustmentStats` is `{}` or `yearlyExtraCents` is 0, `monthly_extra_cents` equals `even_out_cents`. Payment `m` uses `((startMonth + m - 1) % 12) + 1`, and the caller passes the start month rather than the first payment month. Do not read `extrasByMonth` or `indexByMonth` for these fields, and do not write the probe onto the schedule.
